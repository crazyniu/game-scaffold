# 00 新游戏开工清单（AI 按这个顺序做）

从这个底座做一款新游戏的完整步骤。每一步做完都 `./run.sh check` 一次。标「问用户」的步骤要等用户确认再往下走；其余的直接做。

## 第 0 步：开新仓库（不要在底座仓库里改）

```bash
git clone https://github.com/crazyniu/game-scaffold.git <新游戏代号>
cd <新游戏代号>
git remote remove origin
gh repo create <账号>/<新游戏代号> --private --source=. --push   # 或者用户给的仓库地址：git remote add origin <地址> && git push -u origin main
cd client && npm ci && cd ..
./run.sh check          # 底座本身应该全绿：类型检查、35 个测试、关卡校验
```

底座以后修了 bug、加了通用功能，新游戏可以 `git remote add scaffold <底座地址>` 后挑着 cherry-pick；新游戏里修的通用 bug 也回推给底座。

## 第 1 步：改身份（直接做）

| 改什么 | 在哪 |
|---|---|
| 代号（小写字母，存档键前缀、密钥文件名都用它） | `game.json` 的 `codeName`；三个平台实现里的 `const PREFIX = '<代号>.'`（`client/assets/scripts/platform/platform{Debug,Wechat,Native}.ts`，`./run.sh check` 会查两边一致）；`client/package.json` 和 `client/build-config/*.json` 的 `name` |
| 游戏名（每种语言一个，按当地叫法起，不直译） | `game.json` 的 `name`；文案 `BOOT_NAME`（加载页） |
| 包名 | `game.json` 的 `ios.bundleId`、`android.packageName`（问用户要域名前缀） |
| 版本号 | `game.json` 的 `version`、`build`、`ios.build` |
| CLAUDE.md | 第一行游戏名、「这款游戏」一节的一句话玩法和平台 |
| README.md | 换成新游戏的简介（底座的说明留一行链接） |

然后 `./run.sh native-apply`（按 `game.json` 改写各平台工程），提交。

## 第 2 步：写玩法（问用户）

1. 和用户把玩法聊清楚，写进 `docs/01` 第 1–3 节（规则、胜负、事件、技能、失败原因、复活效果），按 `docs/02` 第 5 节排出前 50 关的排布表（第几关出什么玩法、难关在哪、第 41 关起的持平难度），关卡也先只生成前 50 关（`docs/02` 5.7）。**用户确认后再写代码。**
2. 只借鉴「品类玩法」，名称、角色、图标、界面画面一律原创，不照任何现有游戏的截图做（CLAUDE.md 硬性约束 1）。

## 第 3 步：换玩法代码（直接做）

按 `docs/02` 第 3 节：纯逻辑 + 测试 → 关卡参数 → 场地 → 局内外壳里标「玩法」的几处 → 技能 → 失败原因文案 → 任务计数。写量难度的机器人（`core/<玩法>/bot.ts`），定 `levels.json` 的规模和 `targets`，`./run.sh level-pick` 挑候选（`docs/02` 5.8；先 `--probe` 看现状，候选都太容易就先调规模）。`./run.sh check`、`./run.sh level-verify` 通过。

## 第 4 步：调外围数值（先讲方案，用户确认后改）

`economy.json`：功能开放关 `features`、技能价格、生命、宝箱、签到七天、转盘、任务、每日挑战、连击档位、收藏册。`levels.json`：关卡总数、难关间隔、难度曲线。`ads.json`：插屏频控。改完跑 `./run.sh eco-sim`（有广告、`--no-ads` 各一次），把「一天挣多少、花多少、看几次广告」讲给用户。

## 第 5 步：美术（写需求给 Codex，用户验收）

按 `docs/03`：先定风格（第 2 节），再按清单出图。底座里这些是**占位图，必须换**：

| 占位 | 位置 | 换成 |
|---|---|---|
| 30 张示例卡面（彩色几何图形 + 数字） | `client/assets/resources/card/c01..c30.png` + `config/cards.json` + 文案 `CARD_*` | 新游戏的收藏卡（也可以当局内图案） |
| 主页、章节背景（渐变） | `resources/ui/bg/home.jpg`、`chapter_<id>.jpg` | 新游戏场景 |
| 加载页背景、logo（「MY GAME」字） | `client/assets/boot/bg.jpg`、`logo.png` | 新游戏 |
| 应用图标 | `art/approved/logo/logo_1024.png` → `./run.sh native-icons` | 新游戏 |
| 主页展示区的主角 | `game_ui.json` 的 `homeDeco.hero`（用哪几张卡、位置、大小） | 吉祥物 |
| 金币、宝箱、卡背、头像、入口图标、技能图标、关卡类型图标 | `resources/ui/icon/*` | 能沿用就沿用，和新主题不搭的重画（同名替换即可） |
| 结算页两边的角色 | `game/result.ts` 用的 `card/c01`、`card/c02` | 吉祥物 |

平面界面部件（按钮、面板、图标键、白色图标、进度条，`resources/ui/skin/f_*`、`j_btn_*`）是程序画的，换主题色改 `tools/art/flat_skin.py` 的颜色后重跑，不用 Codex。进包后 `./run.sh art-compress`、`./run.sh meta`。

## 第 6 步：文案和多语言（直接做）

`i18n/strings.csv`：游戏名、卡名、章节名、玩法相关的说明和提示、任务名。每种语言按当地休闲游戏的说法写，不直译；放不下就改短，不缩字（`docs/10` 第 8 节）。改完 `node client/tools/i18n.mjs`、`./run.sh font-subset`（要原字体，见 `client/tools/font_subset.py` 开头）。

## 第 7 步：试玩和验收（在 Mac 上，用户验收）

`./run.sh` 试玩（试玩模式资源加满、所有关能点开）、`./run.sh real` 按真实进度、`./run.sh auto` 机器人代打一遍、`./run.sh page shop` 直接看某页。交给用户测时 `./run.sh lan`，把内网地址发给用户。每个界面按 `docs/09` 第 10 节、`docs/08` 第 3 节清单截图审查。

## 第 8 步：上架（用户办资质，AI 打包）

`docs/06` 的清单（资质、隐私政策、商店后台声明）→ `game.json` 换真实的 AdMob 应用 ID 和广告位、微信 appid 和云开发环境、iOS Team ID、隐私政策地址 → 要统计和崩溃报告就把 Firebase 的两个配置文件放进 `firebase/`、打开 `firebase.enabled`（`docs/10` 第 5.1 节）→ `store/listing.md` 写商店文案、`store/briefs/` 写上架图需求 → `./package.sh` 打包（`docs/10` 第 4 节）。

## 不要做的事

- 不改底座的版式和组件去「重新设计」界面（`docs/09` 开头）；要改先问用户。
- 不为平台开分支、不复制工程；平台差异只放 `platform/`、`client/native/`、`game.json`（`docs/10` 第 1 节）。
- 不在 `core/` 里用 `cc`、时间、`Math.random`、存储；不在 `platform/` 以外调 `wx` 或原生桥；不把数值、文案写进代码。
- 不给界面、平台层写单测；CI 只有一条、三分钟内（`docs/05` 第 3、4 节）。
