# 02 玩法接入与关卡

底座带一个能玩的**示例玩法**（三消取块），作用是把局内外壳、外围系统、打包流程全部跑通。做新游戏时**只换玩法这一块**，局内外壳（顶栏、暂存槽、技能栏、连击满屏、复活、失败、结算、教学、提示、演示、代打）照用。

## 1. 玩法由哪几块组成

| 文件 | 层 | 是什么 | 新游戏 |
|---|---|---|---|
| `client/assets/scripts/core/demo/level.ts` | 纯逻辑 | 关卡数据结构、生成、参考解 | **换** |
| `client/assets/scripts/core/demo/rules.ts` | 纯逻辑 | 局面 `GameState`、点击 `tap()`、计时 `tick()`、技能、提示 `hint()`、复活 `revive()`，返回事件列表 | **换** |
| `client/assets/scripts/game/board.ts` | 界面 | 场地：把一关画出来、点了回调、被压住的压暗、提示圈 | **换** |
| `client/assets/scripts/game/gameView.ts` | 界面 | 局内外壳。只有标了「玩法」的几处要改：`start()` 读关卡、`layout()` 里场地和暂存槽、`doTap()`、`play()` 按事件播动画、`update()` 里代打 | 改几处 |
| `client/assets/scripts/game/flow.ts` | 界面 | 局内流程。只有标了「玩法」的几处要改：`hasEffect` / `useSkill` 的技能效果、`LOSE_KEY` / `REVIVE_KEY` 失败原因、`endRun` 的任务计数 | 改几处 |
| `client/assets/scripts/game/labHooks.ts` | 界面 | 难度调试页的整体三档改什么 | 改 |
| `client/assets/resources/config/levels.json` | 配置 | 关卡参数 | **换** |
| `client/tests/demo.test.ts` | 测试 | 玩法规则和关卡可解 | **换** |
| `client/tools/level/verify.ts` | 工具 | `./run.sh level-verify`（CI 跑） | **换** |
| `client/assets/scripts/services/config.ts` | 服务 | `loadLevel()`、`kindOf()` | 改 |

新玩法建议放 `core/<玩法名>/`，把 `core/demo/` 删掉，import 跟着改；`tsc` 会把所有要改的地方报出来。

## 2. 玩法要遵守的接口

**纯逻辑**（`core/`，不 import `cc`，不碰时间、存储、`Math.random`；随机用传入种子的 `Rng`）：

```ts
// 关卡：同一关号每次生成一样；带一条参考解（按这个顺序点一定能过）
generate(cfg, 关卡号, 降档 = 0, 暂存槽加减 = 0): Level   // 或从 config/levels/level_XXXX.json 读
kindOf(cfg, 关卡号): 'normal' | 'hard' | 'boss'

// 局面：就地修改，返回这一步产生的事件；界面只按事件播动画，不自己推导规则
class GameState { status; loseReason; revived; clone(); ... }
tap(s, 点了什么): GameEvent[]          // 点不了返回 []
tick(s, dt): GameEvent[]              // 限时
hint(s): 该点什么 | -1                 // 提示技能、闲置提示、机器人代打共用
revive(s): GameEvent[]                // 复活
use<技能>(s, ...): GameEvent[]
```

事件至少要有 `win`、`lose`（带原因）；其它按玩法定（示例：`move` 进暂存槽、`clear` 消掉三个、`shift` 暂存槽重排、`shuffle`）。

**界面接口**（`gameView.ts` 给 `flow.ts` 用的，换玩法时保留）：`s`、`lv`、`arg`、`combo`、`used`、`moved`、`ended`、`paused`、`items`、`canUndo`、`cleared`（或你的计数）、`undo()`、`act(fn)`、`resync()`、`showSkillHint()`、`refreshSkills()`、`showIntro()`、`startTutorial()`。

**连击**：玩法在「命中」（示例：消掉一组）时调 `this.hitCombo(x)`，满屏特效、金币、夸奖全部是底座的。

## 3. 换玩法的步骤

1. 在 `docs/01` 第 1–3 节写清规则（胜负、事件、技能效果、失败原因），用户确认。
2. 写 `core/<玩法>/level.ts`、`rules.ts` 和测试（`client/tests/<玩法>.test.ts`）：每条规则、每个技能、胜负边界各一两个用例；关卡全部可解。`./run.sh test` 通过。
3. 改 `config/levels.json`（参数）、`core/config.ts` 的 `LevelsConfig` 类型、`services/config.ts` 的 `loadLevel()`。
4. 写 `game/board.ts`（场地），改 `gameView.ts`、`flow.ts` 里标了「玩法」的地方。技能有变就改 `economy.json` 的 `skills.order`、`toolPrice`、`toolStart`、`features.skill_<id>`、技能图标 `icon/skill_<id>.png`、文案 `H_SKILL_<ID>`、音效（`services/audio.ts` 的 `MAP`）。
5. 失败原因文案 `UI_LOSE_*`、复活效果 `REVIVE_*`、开局说明 `TIP_*`（挂在 `game_ui.json` 的 `tips`）、加载页小提示 `BOOT_TIP_*`。
6. 每日任务里和玩法有关的计数（示例 `clear`）：改 `flow.ts` 的 `endRun`、`economy.json` 的 `tasks.pool`、文案 `TASK_NAME_*`、图标。
7. `./run.sh check`、`./run.sh level-verify` 通过，再去 Mac 上 `./run.sh` 试玩、`./run.sh auto` 让机器人代打一遍。

## 4. 关卡

- **进包的关卡必须可解**（CLAUDE.md）：生成时带参考解，`level-verify` 逐关按参考解打一遍。示例玩法的做法是「按解构造」：先排出一个合法的取块顺序，再按顺序每三个配同一种图案——照顺序点一定能过。新玩法尽量也这么做，比生成完再求解快得多、也不会漏。
- **两种关卡来源**：现场生成（示例：`levels.json` 是参数，关卡号就是种子，包里没有关卡文件，最省包体）；或者离线生成关卡文件（`config/levels/level_XXXX.json`，可以逐关挑、逐关调难度，适合难度要精调的游戏；微信版放到网上下载，见 `docs/04` 第 7 节）。
- **难度曲线和节奏**：按第 5 节排。示例：每 `hardEvery` 关一个难关（多一种图案，第 15 关起限时），每 `bossEvery` 关一个超难关，难关之后那一关放松（`release`），连输 `easeAfterFails` 次后降一档。
- **降档变体**：`generate(..., ease)`，每档更容易一点（示例：少一种图案）。

## 5. 关卡节奏与难度曲线（新游戏照这个排）

这一节是排关卡的默认原则。新游戏在 `docs/01` 第 2 节写出自己的排布表（第几关出什么），对照这里检查；要偏离先讲理由、用户确认。

### 5.1 两个最常见的错

1. **难度和新东西铺得太靠后**：多数玩家打不到第 80 关，排在那里的机关等于没人看到；前面又太简单，没有理由用道具、看广告。
2. **单局越来越长**：靠「多放东西」加难度，后期一关要三五分钟，玩家开始觉得拖。同类游戏里做得好的，中后期仍不断插短关；做得差的，从第 40 关左右起几乎关关超过 1 分钟（见 5.6 的参考）。

### 5.2 默认排法

| 项 | 默认 |
|---|---|
| 首版关卡数 | 100–120 关，每章 20 关；以后按数据加 |
| 教学 | 前 3 关怎么点都能过，一关只教一件事 |
| 第一次会输 | 第 4–6 关起开始有真实的失败 |
| 难度到平台 | 第 30 关左右到平台；之后**章内持平、每章小幅上一个台阶**，起伏靠难关、超难关。不随关卡号一直往下压（压到后面全是 5% 的关，人就走了），也不完全不涨（道具和金币会失去压力，经济设计跟着失效） |
| 单局时长 | 普通关 40–90 秒，难关 2 分钟以内，超难关 2 分半以内；每章插几关 30 秒左右的短关。后期加难度靠种类、机关组合、规定路线，不靠堆数量 |
| 难关 | 每 5 关一个难关；超难关每 10–20 关一个，**第一个不早于第 15 关** |
| 放松 | 难关、超难关之后的那一关一定是短关、明显轻松 |
| 新东西 | 前 10 关每关最多一样新东西，两样之间至少隔一关；之后平均每 5–6 关一样；所有机关在全部关卡的前 40% 内出完，但每章至少留一样新东西（机关的变体、新画面），后半段不能整章没有新鲜感 |
| 机关首发 | 首发关是教学关（比同位置容易一截），之后 2–3 关单独练，再和旧机关组合 |
| 先教后用 | 道具解锁关强制教学并送一个；之后一两关内安排一关正好用得上它的难点 |
| 限时 | 只给难关、超难关；第一次限时不和第一个超难关在同一关 |

一个 5 关的周期（难关在第 5 关）：**放松短关 → 普通 → 普通 → 稍难 → 难关**。

### 5.3 「前面太简单」先查这几样

难度感受不到时，多半不是关卡本身的问题：

- **免费道具**：前几关道具全免费、撤销不限次（`economy.json` 的 `skills.freeAllUntil`、`toolMaxFree`），玩家走错就撤，规定路线的难度直接没了。免费期越长，前面越像「无脑过」。
- **试玩模式**：`./run.sh` 默认资源加满。验收难度用 `./run.sh real`，并且不用道具打。
- **尺子和真人不一样**：机器人量出来的是「随手点 / 想几步 / 想清楚」三种人的过关率；认真玩、会看预告的人接近「想清楚」那一档，对他来说比尺子说的容易得多。定目标时要想清楚这一关是给哪种人设计的。

### 5.4 怎么落到配置里（示例玩法）

`config/levels.json`：`segments` 管难度曲线（前 3 关教学、第 30 关左右到平台）；`hard` / `boss` 管难关多难；`release` 管难关之后怎么放松；`clock.from` 管从第几关起限时；`pace` 管时长上限（估算 = 点击次数 × `tapSec` + 完成次数 × `doneSec`）。`./run.sh level-verify` 会列出超时长的关，`client/tests/demo.test.ts` 守着「不超时长」「难关后放松」两条。换玩法时把估算公式换成自己的（每次点击、每次完成各算几秒），时长最好拿机器人按真人速度打一遍量。

### 5.5 排布表模板（写进 `docs/01` 第 2 节）

| 关 | 内容 | 类型 | 估算时长 |
|---|---|---|---|
| 1–3 | 基本操作（教学） | 普通 | 15–30 秒 |
| 4 | 第一个道具解锁，强制教学 + 送一个 | 普通 | |
| 5 | 第一个难关，正好用得上这个道具 | 难关 | |
| 6 | 放松短关 | 普通 | 30 秒 |
| … | 每样新东西：首发（教学）→ 单独练 2–3 关 → 和旧的组合 | | |

### 5.6 参考（个人分析文章，不是官方数据，只当参考）

- Pixel Flow：作者自己按第 1–20 关各打 10 遍，第 18 关教了强力道具、送一个，第 19 关平均用时从 26 秒跳到 165 秒，是唯一稳定会输的一关；作者也说不确定是不是有意设计。[Gamigion：Interesting Tricks in Pixel Flow](https://www.gamigion.com/interesting-tricks-in-pixel-flow/)
- 同玩法的后来者：作者一个人打到第 100 关，平均每关比 Pixel Flow 长约 12 秒；后来者从第 41 关左右起几乎关关超过 1 分钟，有连续 23 关超过 1 分钟的；Pixel Flow 中后期仍不断插入 40 秒以内的短关，Very Hard 之后给明显的放松。[Gamigion：Why did the latecomers fail](https://www.gamigion.com/why-did-the-latecomers-built-on-essentially-the-same-core-play-fail-to-produce-the-same-result/)

## 6. 难度怎么量（做精调时用）

- **尺子只用屏幕上看得到的信息**：用「只看屏幕、按常人习惯点」的机器人量过关率（随手点的定难度、想清楚的守住公平），不能用全知求解器的容错当尺子——求解器说「有解」不等于玩家过得去。
- **目标按章节持平、逐章小幅变难**：见 5.2；难关、超难关单独定目标。
- **难在点击顺序**：好的难关是「想清楚能过、随手点会输」，而不是「怎么点都看运气」。
- 改难度前先用机器人量现状，改完再量；根本性的调整先讲思路、用户确认后再动手。
- 底座给了量具的位置：`core/<玩法>/rules.ts` 的 `hint()`（贪心玩家）就是最简单的机器人；`./run.sh auto` 在浏览器里代打；难度调试页（`docs/10` 第 9 节）能在开发版里切换每关的难度档、看演示。
