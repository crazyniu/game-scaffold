# 04 技术架构

## 1. 选型

| 项 | 选择 | 说明 |
|---|---|---|
| 引擎 | Cocos Creator 3.8.8 | 微信小游戏、Android、iOS、网页都是官方构建目标；Mac 上装在 `/Applications/Cocos/Creator/3.8.8/` |
| 语言 | TypeScript 严格模式 | |
| 工程 | 仓库的 `client/` | |
| 界面 | 全部由代码生成，一个场景 `main.scene` 只挂 `Boot` | 不拖 prefab，Linux 上也能写界面 |
| 单元测试 | Node 自带 `node --test` + `tsx`，只测 `core/` | Linux 上能跑，不要 Cocos |
| 静态检查 | `tsc`（核心、工具、界面层三份配置）+ `./run.sh check` 里的几条 grep | |
| 后端 | 无 | 存档本地 + 平台云存档；排行榜用平台能力 |

## 2. 目录

```

tools/

  native/                 # 按 game.json 改写原生工程（apply.mjs）、生成应用图标（icons.py）
  wechat/                 # 微信版资源挪到网上（remote.mjs）、PNG 无损重压、清旧资源（prune.mjs）
  web/serve.mjs           # 内网试玩服务

    scripts/

        meta/             #   外围系统：生命、金币、技能、星级、宝箱、签到、任务、转盘、收藏、每日挑战、连击、存档结构
        rng/  util.ts  config.ts（配置表的类型）

      platform/           # 平台层：PlatformBase 接口 + debug / wechat / native 三个实现
      ui/                 # 界面框架：kit（部件）、fx（动画）、shell（页面与页头）、popup / popups（弹窗）、screen（适配）、scroll、i18n、res（资源）、loading（加载页）、mockAd
      game/               # 局内：gameView（外壳）、board（示例场地）、flow（局内流程）、result（结算）、levelKind、labHooks
```

依赖方向只能向下：`pages / game → ui → services → core`，`services → platform`。`core` 不依赖任何人；`platform` 不碰界面（模拟广告页由 `Boot` 注入）。

## 3. 启动流程（`Boot.ts`）

画布与相机 → 加载页（boot 包）→ 读 resources 包（微信版从网上下）→ 平台初始化、配置、存档 → 文案 → 字体 → 首页要的图 → 界面外壳、注册页面 → 主页。每一步按量占一段进度；失败前 3 次悄悄重试，之后显示「重试」，后台照样隔一会儿再试。首页出来以后在后台接着读局内图、卡面、结算图。

调试构建（`./run.sh` 打的）：控制台 `gsDebug.ui.go('shop')`、`gsDebug.Popups.livesPopup()` 直接开页面和弹窗；没接住的错误画在屏幕顶上；地址栏参数 `?level=N&play=1`、`?autoplay=1`、`?page=名字`、`?real=1`、`?notch=1`、`?capsule=1`、`?ads=0/1`（`services/launch.ts`）。

## 4. 核心逻辑

- 玩法规则是确定性状态机：就地修改局面，返回这一步的事件列表；界面只按事件播动画、不自己推导规则；逻辑瞬时完成、动画追帧，连点不丢输入（`docs/02` 第 2 节）。
- 外围系统 `core/meta/*`：每个模块是一组纯函数，参数是存档、配置、当前时间（秒）、日期（天号）、随机数，返回结果并就地改存档。界面层取时间用 `services/clock.ts`。
- 随机数 `core/rng/rng.ts`（mulberry32，可播种、跨平台一致）。

## 5. 平台层

`platform/platformBase.ts` 定义接口，`platform/index.ts` 启动时按运行环境挑一个实现：

```ts
showRewarded(placement): Promise<'done' | 'skipped' | 'unavailable'>
showInterstitial(placement): Promise<boolean>
showBanner(placement) / hideBanner()
adsAvailable(): boolean                  // 现在能不能播；不能时入口变灰
onAdsChange                              // 广告拉到了 / 同意变了
getProfile() / getRankList(board) / submitScore(board, value)
loadData(key) / saveData(key, value)
share(payload) / vibrate(kind) / track(event, params)
hasCapability(cap): boolean              // 'ads' | 'share' | 'friend_rank' | 'ad_test' | 'privacy_options' | 'health_notice' …
launchQuery() / systemLanguage() / safeArea() / menuButton()
isDevBuild() / openPrivacyPolicy() / openPrivacyOptions()
```

| 实现 | 调用 | 广告 | 存档 |
|---|---|---|---|
| `debug`（浏览器试玩） | 无 | 模拟广告页（看完 / 中途关闭 / 加载失败）；跟着 `game.json` 的 `ads.enabled`，`?ads=0/1` 临时改 | `localStorage`，键前缀 `<代号>.` |
| `wechat` | `wx` | 流量主（激励、插屏、横幅；`game.json` 的 `ads.wechat`，空着 = 没广告） | 本地 |
| `native`（iOS、Android 共用一份 TS） | 原生桥（`jsbBridgeWrapper` 的 `game.*` 事件） | AdMob + UMP（iOS 再加 ATT） | 本地 |

规矩：`wx`、原生桥只出现在 `platform/`；业务代码按 `hasCapability` 分支，不按平台 id 分支。广告都有超时兜底：播不出来按没播算，看广告的入口一定撤遮罩，不卡流程。

## 6. 存档

- 一个可直接转 JSON 的对象（`core/meta/save.ts` 的 `SaveData`，`playerData.ts` 的 `create` / `load`），带 `version`。开发期不迁移：版本不对开新档，缺的字段补默认值；上线后结构再变才写迁移函数。
- 关键节点（过关、花钱、领奖）立即写本地（`services/save.ts`）。写失败不抛给调用方：提示「进度没存上」，5 秒后再写，内存里的进度照常。
- 时间相关（签到、每日计数、周）用本地时间，不防改时间。

## 7. 包体与加载

- PNG 一律量化成 256 色调色板（`./run.sh art-compress`，`check` 会查）；背景音乐 mp3；引擎只留用到的模块（2D、UI、遮罩、绘图、缓动、音频）。
- **微信版的资源放在网上**：小游戏主包 ≤ 4 MB，安装包里只有引擎（用微信引擎插件，不占下载）、脚本、boot 包（加载页和字体）；整个 `resources` 包放云开发的静态网站托管，加载页下载、显示进度、失败重试（`docs/10` 第 4 节）。字体必须在 boot 包（网上下的 TTF 微信注册会失败）。
- 首页之前只读首页要的图（`ui/res.ts` 的 `startupFrames`），其余后台读；`img()` 遇到没读的图先占位、读到再显示；进关时等这关必需的图，装饰图最多等 2 秒。
- 一闪而过的特效小图走对象池（`fxImg` / `recycleFx`）；看不见的东西直接隐藏；每帧的 `update` 里不分配。
- iOS、Android、网页版资源都在包里。

## 9. 音效

`services/audio.ts`：短音效启动时读，`sfx(名字)` 播；连击命中沿五声音阶逐级升调（`hit_0..10`），升档四档（`tier_1..4`）；高频音（点中、落位）有几个音高版本随机播。背景音乐第一次触摸后才能出声。震动 `buzz('light' | 'medium' | 'heavy')`，受设置开关控制。音效来源和合成脚本在 `client/tools/audio/`（合成音、乐器采样、CC0 音效包，许可在同目录）。
