# 06 平台发布

> 平台政策变得快。下面是 2026-11 整理的理解，**每一条在提交前都要对着官方最新文档核对**，核对后在本文件写上日期。标 ⏳ 的是办理周期长、要尽早启动的事项。

最后核对日期：未核对

## 1. 需要用户尽早办的事

平台：微信小游戏（中国大陆）、Google Play 和 iOS（只上海外，不上中国大陆商店，不办版号）。不做内购；上架的版本有广告：iOS、Android 接 AdMob，微信只用微信官方的流量主（不用 AdMob）。这是底座默认的范围，新游戏不同就改这里和 CLAUDE.md。

| 事项 | 用于 | 说明 |
|---|---|---|
| ⏳ 小游戏注册与实名 | 微信 | 每款游戏一个小游戏账号；个人主体能不能实名看证件，走不通要借大陆的个人或公司当主体 |
| ⏳ 计算机软件著作权或电子版权认证 | 微信 | 每款游戏一份；电子版权认证约 10–15 天，普通软著一两个月 |
| ⏳ ICP 备案 | 微信 | 每个小游戏都要，在微信后台办，约 1–3 周 |
| ⏳ Google Play 开发者账号 | Google Play | 个人新账号正式发布前要完成一段封闭测试（凑够测试人数、持续两周左右）；账号可以多款游戏共用 |
| ⏳ Apple 开发者账号 | iOS | 每年年费；Team ID 填 `game.json` 的 `ios.team`；多款游戏共用 |
| 隐私政策网页 | 三端 | 可公开访问的 URL，填 `game.json` 的 `privacyPolicy`；有广告，要写清楚 AdMob 收集广告 ID 等数据、用于投放广告 |
| app-ads.txt | iOS、Android | `store/app-ads.txt` 换成自己的发布商 ID，放到开发者网站根目录；两个商店后台的「开发者网站」都填这个网站。没有它 AdMob 会限制填充 |
| ⏳ AdMob 应用与广告位 | iOS、Android | AdMob 后台为每端建一个应用（得到应用 ID，填 `game.json` 的 `ios.admobAppId` / `android.admobAppId`），各建激励、插屏、横幅三个广告位（填 `ads.ios` / `ads.android`）。上架以后把应用关联到商店页面，过 AdMob 的应用审核才正式投放 |
| 商标查询 | 三端 | 游戏名各语言版本没有同类目在先商标、微信小游戏名称未被占用 |

微信小游戏开通流量主后在微信后台建广告位，填进 `game.json` 的 `ads.wechat`。

## 2. 微信小游戏

- 包体：主包 ≤ 4 MB。安装包里只放引擎、脚本和加载页，其余资源放云开发的静态网站托管、加载页里下载（`docs/04` 第 7 节，`docs/10` 第 4 节）。托管的域名要加进「downloadFile 合法域名」。
- 类目：休闲游戏。提交软著、自审自查报告。
- **提交审核时网络类型选「联网」**：资源要从网上下载，选错了微信按离线模式审，`wx.downloadFile` 直接报 `api can't use in offline mode`，停在加载页、被驳回「打不开」（踩过）。
- 变现：流量主（激励视频、插屏）。个人主体的小游戏累计独立访客满约 500 人才能开通（以后台为准），上线初期没有广告：看广告的按钮自动隐藏（`ads.wechat` 空着），有金币价的改用金币，靠前期关卡简单撑过。
- 不接虚拟支付（需要版号）。
- 必做：用户隐私保护指引、隐私授权弹窗；好友榜走开放数据域，主域拿不到好友数据。
- 分享：不得诱导分享（「分享才能继续」「分享得奖励」都不行）。分享不给任何奖励，只有普通转发。
- 内容：不出现赌博式抽奖表述；收藏开卡的概率要在界面里公示。

## 3. iOS（只上海外）

- 产物：Cocos 出 Xcode 工程，在用户的 Mac 上打包签名、传 App Store Connect。上架区域不选中国大陆（大陆上架游戏要版号）。
- 设备：只做 iPhone 版（`TARGETED_DEVICE_FAMILY = 1`），在 iPad 上按 iPhone 比例运行，不交 iPad 截图。
- 语言：`game.json` 的 `languages.app`（`docs/10` 第 8 节）；App Store Connect 里每种语言填一份商店文案（`store/listing.md`）。
- 广告：AdMob；启动时先弹 UMP 同意表（只有需要的地区），再弹 ATT 跟踪授权（不同意也能玩，只是广告不个性化）。App Store Connect 的 App 隐私按 AdMob 填：收集「标识符（设备 ID）」「使用数据（广告数据）」「诊断」，用于第三方广告，「是否用于跟踪」选是（Google 的说明：https://developers.google.com/admob/ios/privacy/data-disclosure ）。
- 统计和崩溃报告（`game.json` 的 `firebase.enabled` 开着时，`docs/10` 第 5.1 节）：App 隐私在上面的基础上再勾「使用数据（产品交互）」「诊断（崩溃数据、性能数据）」，用于分析、App 功能，不用于跟踪（Firebase 的说明：https://firebase.google.com/docs/ios/app-store-data-collection ）。
- 内购：这一版不做。以后做时用 StoreKit，去广告为非消耗型、金币包为消耗型，必须有「恢复购买」；数字商品只能走苹果内购。
- 抽奖与宝箱：各奖品和各稀有度的概率在抽奖页、收藏页公示（这一版金币不卖，但公示一直保留，以后开内购也不用补）。
- 排行榜与云存档：Game Center、iCloud。
- 分级：App Store 年龄分级问卷，按 12+ 左右填（有随机奖励；以后开了广告也是这一档）。

## 4. Google Play

- 产物：AAB（Google Play 不收 APK；APK 只给自己装手机测试），仅 arm64-v8a + armeabi-v7a，用上传密钥签名、真实广告位（`./package.sh` → 3 Android → 2 AAB）。`targetSdk` 36（`game.json` 的 `android.targetSdk`；Google Play 2026-08-31 起新应用和更新都要 Android 16 / API 36，每年 8 月底跟着提一级，提交前核对）；清单里 `android:appCategory="game"`（API 36 起大屏会忽略「只能竖屏」，游戏不受约束）。需支持 16 KB 内存页：`./package.sh` 打完 AAB 自动用 NDK 的 `llvm-readelf` 查 arm64 原生库是否按 16 KB 对齐。
- 语言：`game.json` 的 `languages.app`。上架地区为海外，含台湾、香港。
- 代码优化与依赖版本（2026-11-27，fishsort #234 带过来的，Play 管理中心「建议采取」那几条）：release 用 R8，默认配置必须是 `proguard-android-optimize.txt`（`proguard-android.txt` 带 `-dontoptimize`，只缩不优化，Play 会提示「请使用 R8 优化」，Android Gradle 插件 9.0 起也不再支持它）；我们自己的 Java 都在 `com.cocos.game`，由 `proguard-rules.pro` 的 `com.cocos.**` 保留规则护着，JS 反射调用不会被删。Play 提示某个 androidx 库「SDK 版本已过时」时，多半是广告、统计 SDK 间接带进来的，在 `app/build.gradle` 里显式声明新版本（先核对它的 `minCompileSdk` 和插件版本要求）。改完要真机试启动、三种广告、同意弹窗和统计：优化引起的问题只出在正式包。
- 受众：目标年龄设为 13 岁以上，避开家庭政策对广告 SDK 的额外限制；商店素材不要做得明显面向幼儿。
- 广告：AdMob，接 UMP 同意弹窗（欧洲经济区等地区必需），清单里声明广告 ID 权限；**去掉应用内购买权限**（`com.android.vending.BILLING`，是依赖库合并进来的，`AndroidManifest.xml` 里用 `tools:node="remove"` 删掉；这一版不做内购，带着它 Play 会标「含应用内购买」）。Wi-Fi 和竖屏两项硬件在清单里标成非必需（`uses-feature … required="false"`）：不标的话 Play 会按 Wi-Fi 权限和竖屏方向推断设备必须有，没有的平板、Chromebook 装不了。Play 后台「广告」声明选「含广告」，「广告 ID」选用于广告；数据安全表单按 AdMob 填：收集设备或其他 ID、应用互动、诊断数据，用于广告，和第三方共享（Google 的说明：https://developers.google.com/admob/android/privacy/play-data-disclosure ）。
- 统计和崩溃报告（`firebase.enabled` 开着时）：数据安全表单再加「应用活动（应用互动）」「应用信息和性能（崩溃日志、诊断）」「设备或其他 ID」，用于数据分析，传给 Google 处理（Firebase 的说明：https://firebase.google.com/docs/android/play-data-disclosure ）。
- 内购：这一版不做。以后做时用 Play Billing，去广告为非消耗型、金币包为消耗型，提供「恢复购买」。
- 必填：数据安全表单、内容分级问卷、广告声明、隐私政策链接（不收集数据也要有隐私政策链接）。
- 抽奖与宝箱：各奖品和各稀有度的概率在抽奖页、收藏页公示（以后开内购、金币能用钱买时，这是苹果和台湾法规都要求的）。
- 排行榜与云存档：Play Games Services v2。

## 5. 三端差异总表

| 功能 | 微信小游戏 | Google Play | iOS |
|---|---|---|---|
| 地区 | 中国大陆 | 海外（含台湾） | 海外（含台湾），不上中国大陆 |
| 激励视频 | 流量主（开通以后） | AdMob | AdMob |
| 插屏 | 同上 | 同上 | 同上 |
| 统计、崩溃报告 | 不接（用微信后台的数据） | Firebase（开着时） | Firebase（开着时） |
| 内购 | ❌ | 这一版不做 | 这一版不做 |
| 排行榜 | 好友榜 | Play Games | Game Center |
| 分享得奖 | ❌（只做普通分享，三端都不给奖励） | ❌ | ❌ |
| 添加到桌面 | ✅ | — | — |
| 包体 | 主包 ≤ 4 MB，其余分包或远程 | 全部打进安装包 | 全部打进安装包 |
| 语言 | `languages.wechat`（简体中文、英文） | `languages.app`（12 种，英文默认） | 同 Google Play |

## 6. 提审前检查

- [ ] 第 1 节资质齐全
- [ ] 隐私政策与实际采集一致，弹窗在采集前出现
- [ ] 无广告填充时全流程可玩（看广告的入口变灰，不卡流程）
- [ ] 上架包是用 `./package.sh` 的 iOS IPA / Android AAB 打的（只有这两种用真实广告位，其它产物用 Google 的测试广告位）；装上以后看到的广告不带「Test Ad」字样
- [ ] 测试时不要点自己的真实广告（会被 AdMob 判成无效流量，严重的封号）；要在真机上试真实广告，先在 AdMob 后台「设置 → 测试设备」加上自己的手机
- [ ] 商店后台的广告、跟踪、数据收集声明和包里实际一致（含广告、iOS 有跟踪授权）
- [ ] 两个商店的开发者网站填的是放了 app-ads.txt 的那个网站；AdMob 后台的 app-ads.txt 显示「已验证」（上架并关联商店后 AdMob 才去抓，要等一两天）
- [ ] 断网可玩（小游戏首次加载除外）
- [ ] 包体在预算内
- [ ] 正式版里没有「难度调试」：它只在 `./run.sh` 打的调试构建里出现（`PlatformBase.isDevBuild`），`./package.sh` 打的包一律不出，不用改开关（`docs/10` 第 9 节）。各档关卡 `config/levels_lab/`（有的话）打包时自动挪出、不进包
- [ ] 美术、名称、图标无雷同（对照 `docs/03` 第 1 节）
- [ ] 概率公示页存在
- [ ] 各语言文案无缺失（`client/tests/config.test.ts` 查了一部分，提交前每种语言打开看一遍）
- [ ] iOS 拒绝 ATT 后能正常玩
- [ ] `game.json` 里没有 TODO：AdMob 应用 ID 和广告位、微信 appid、iOS Team ID、隐私政策都换成了自己的
- [ ] 开了 Firebase 的：上架包打包时没有「没带 Firebase」「符号没传上」的提示；装上以后 Firebase 后台能看到 `first_open`、`level_start`
- [ ] 低端机性能达标
