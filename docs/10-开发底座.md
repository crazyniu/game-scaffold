# 10 开发底座：一套仓库出三端，做新游戏照着走

这个仓库（game-scaffold）是所有新游戏的开发底座：以后做的都是同类玩法的竖屏休闲游戏，流程一样。这份文档说明：哪些是底座（换游戏照用）、哪些是游戏自己的（要换）、三端怎么打包上架、多语言和调试页怎么用。做新游戏的步骤见 `docs/00`。

## 1. 一个仓库、一个主干

三个平台：**微信小游戏**（中国大陆）、**Google Play** 和 **App Store**（只上海外）。同一套代码、同一个主干，三端各出一个包。**不为平台开分支、不复制工程**；平台差异只放在下面三处：

| 差异放哪 | 是什么 |
|---|---|
| `client/assets/scripts/platform/` | 平台实现：`platformWechat.ts`（微信）、`platformNative.ts`（Android 和 iOS 共用）、`platformDebug.ts`（浏览器试玩、截图）。启动时 `index.ts` 按运行环境挑一个。业务代码只认 `PlatformBase`，按 `hasCapability` 分支，不按平台 id 分支 |
| `client/native/engine/` | 原生工程：Cocos 的模板 + 我们的桥（iOS `ios/game/GameBridge.mm`、Android `android/app/src/com/cocos/game/GameBridge.java`），收脚本发来的 `game.*` 事件，调广告、震动、分享 |
| `game.json`（仓库根目录） | 这款游戏的身份：名字、版本号、包名、AdMob 应用 ID 和广告位、微信 appid。打包前 `tools/native/apply.mjs` 按它改写构建配置、Info.plist、AndroidManifest、`config/platform.json` |

## 2. 底座和游戏内容的分界

| 底座（换游戏照用，只修 bug、加通用功能） | 游戏自己的（做新游戏要换） |
|---|---|
| `platform/`、`client/native/engine/`、`tools/native/`、`tools/wechat/`、`tools/store/`、`run.sh`、`package.sh` | `game.json`（身份、包名、广告位、appid） |
| 界面框架 `ui/`（部件、动画、页面切换、页头、弹窗、适配、安全区、文案 `tr()`、加载页） | 玩法 `core/demo/`、场地 `game/board.ts`、`config/levels.json`、`tests/demo.test.ts`、`tools/level/verify.ts`（`docs/02`） |
| 局内外壳 `game/gameView.ts`、`flow.ts`、`result.ts`、`levelKind.ts`（只改标「玩法」的几处） | 局内外壳里标「玩法」的几处、`game/labHooks.ts` |
| 页面 `pages/`（主页、商店、地图、选关、任务、每日挑战、转盘、收藏、签到、个人资料、锁页） | 主页展示区、页面背景和图标（`docs/00` 第 5 步的占位图） |
| 外围系统 `core/meta`（金币、生命、技能、星级、宝箱、签到、任务、转盘、收藏、每日挑战、连击、存档） | 数值 `config/economy.json`、`cards.json`、`game_ui.json`、`ads.json` |
| 开发版调试工具 `devtools/`（难度调试页） | |
| 金币模拟 `tools/economy/sim.ts`、文案和字体工具、包体压缩、`.meta` 生成 | |
| 文档的结构和底座部分（`docs/00`、`04`–`06`、`08`–`10`） | `docs/01`–`03`、`07` 的游戏内容；`store/` 的文案和图；`i18n/strings.csv` 里游戏相关的条目 |

## 3. 做一款新游戏

按 `docs/00-新游戏开工清单.md` 走：开新仓库 → 改身份 → 写玩法（用户确认）→ 换玩法代码 → 调数值 → 美术 → 文案 → 试玩验收 → 上架。

## 4. 打包

在装了 Cocos Creator 3.8.8 的 Mac 上运行 `./package.sh`，输入编号并回车。脚本使用当前工作区；微信、iOS 和 Android 在构建前应用 `game.json`。主菜单输入 0 退出，子菜单输入 0 返回。

| 平台编号 | 产物编号 | 产物 |
|---|---|---|
| 1 微信小游戏 | — | 微信开发者工具工程 `client/build/wechatgame`；资源另放 `client/build/wechatgame-remote/remote`，要传到云存储 |
| 2 iOS | 1 | Xcode 工程 `client/build/ios/proj/*.xcodeproj` |
| | 2 | 模拟器 App |
| | 3 | 未签名真机 App |
| | 4 | `client/build/ios/release/*.ipa` |
| | 5 | 装到手机：用开发证书签名，装到和这台 Mac 配对、连得上的 iPhone 并打开（测试广告位；手机要解锁、开着「开发者模式」） |
| | 6 | 上传 App Store Connect：把上一次「4」打好的归档用 Xcode 里登录的账号直接传上去，不用 Transporter |
| 3 Android | 1 | 调试用 APK |
| | 2 | 上架用 AAB |
| | 3 | Gradle 工程 `client/build/android/proj` |
| 4 网页版 | — | `client/build/web-mobile` |

**第一次打包前要准备的**：

- **iOS**：Xcode。Apple 开发者账号在 Xcode → Settings → Accounts 里登录；Team ID 填进 `game.json` 的 `ios.team`。`game.json` 开着广告时，广告 SDK（Google Mobile Ads + UMP）打包时自动下载到 `client/native/engine/ios/sdk/`（不进仓库）；下不下来照样能编，只是没有广告。Xcode 27 要求最低 iOS 15。在模拟器里跑要另外下载 iOS 模拟器运行时（Xcode → Settings → Components）。
- **Android**：Android Studio（带 SDK、NDK、JDK）。SDK、NDK 路径不用去 Cocos 偏好设置里填：`./package.sh` 按 `ANDROID_HOME` → `~/Library/Android/sdk` → 外接盘 `/Volumes/*/Android/sdk` 的顺序找 SDK，NDK 用 `ANDROID_NDK_HOME` 或 SDK 里 `ndk/` 下最新的版本，写进一份不进仓库的构建参数 `client/build-config/.android.local.json` 交给 Cocos。正式包要签名：上传密钥（`.jks`，不进仓库，丢了要找 Google 重置）和 `~/.gradle/gradle.properties` 里的 `RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` 四项。第一次选 AAB 时没有，`./package.sh` 会让你输入密码、生成密钥（默认 `~/keys/<代号>-upload.jks`）并写好这四项；注意 `~/.gradle/gradle.properties` 是整台 Mac 共用的，第二款游戏要用自己的密钥时，把这四项改成按工程配置（或打包前换掉）；生成完把密钥文件和密码备份到别处。打完核对 AAB 带签名。
- **微信**：微信开发者工具；`game.json` 的 `wechat.appid` 换成自己的。资源放在云开发的**静态网站托管**（安装包只能 4 MB，`docs/04` 第 7 节）。没用云存储：免费体验环境改不了云存储的读权限（默认只有创建者能读，游戏下载会 403），静态托管的文件默认所有人可读（用 tcb 试过）。第一次要：
  1. 小游戏后台开通云开发，**环境 ID** 填进 `game.json` 的 `wechat.cloudEnv`。
  2. 静态托管的域名填进 `wechat.remoteUrl`（`tcb hosting detail` 最后一行）。
  3. 小游戏后台 → 开发管理 → 服务器域名，把这个域名加进「downloadFile 合法域名」（开发者工具里预览前也可以先在「详情 → 本地设置」勾「不校验合法域名」）。
  4. 上传：装了云开发命令行（`npm i -g @cloudbase/cli`，`tcb login`）时 `./package.sh` 自动传（`tcb hosting deploy`）；没装就在云开发控制台「静态网站托管」里把 `client/build/wechatgame-remote/remote` 整个文件夹传到根目录。文件名带 MD5，改过的资源换了名字；托管上只留有用的文件，但「有用」要按**还在用的所有包**算：线上版、审核版、体验版可能是三个不同的包，各自引用自己那批文件。所以上传后**不自动清**：打包时 `tools/wechat/remote.mjs` 把这个包用到的文件写进 `remote/_builds/<资源编号>.json` 一起传上去，并打印资源编号（版本号 + 这批文件的内容哈希，如 `1.0.0-3f9a0c1d2e4b`：内容不同编号一定不同，同一分钟打两个包也不会互相覆盖清单），用微信开发者工具上传时把它写进版本备注。要清旧文件时，到小程序后台看线上版、审核版、体验版的备注，把还在用的编号都填上：`node tools/wechat/prune.mjs <环境 ID> --keep 编号1,编号2`（先预演，列出要删的；确认后加 `--yes` 才删）。给的编号在托管上找不到清单就整个停下，一个都不删。
  - `remoteUrl` 空着时资源留在包里：开发者工具的模拟器能跑，预览和上传会超过 4 MB。试打包量主包大小时可以临时 `WECHAT_REMOTE_URL=https://example.com/ ./package.sh`。只打包、先不上传：`NO_UPLOAD=1 ./package.sh`。
  - 云开发费用见 的问答：个人版每月十几到几十元，超出的下载流量 0.21 元/GB。

**Cocos 3.8.8 + Xcode 27 的几处坑**（编通时绕过的，都写在 `client/native/engine/ios/CMakeLists.txt` 和 `package.sh` 里，换引擎或 Xcode 版本时先看这里）：

| 现象 | 原因 | 怎么绕的 |
|---|---|---|
| 部署版本报错 | Xcode 27 最低 iOS 15 | `game.json` 的 `ios.minVersion` 15.0 |
| 引擎编译报 `'is_floating_point' cannot be specialized` | 新 libc++ 不许特化标准库模板，引擎带的 enoki/half.h 这么做了 | 对引擎目标加 `-Wno-invalid-specialization` |
| 链接失败，警告 libwebp.a「not 8-byte aligned」 | Cocos 预编译的 libwebp.a 和新链接器不兼容，Xcode 27 去掉了旧链接器 | 关掉 WebP（`USE_WEBP OFF`，强制写进缓存），打包时用 libtool 重新打包一份给引擎的 `webp` 目标 |
| 模拟器版链接失败 | 同上，x86_64 那部分 | 模拟器版只编 arm64（Apple 芯片的 Mac） |
| 链接报 `__swift_FORCE_LOAD_$_swiftCompatibility51` 找不到 | 广告 SDK 里有 Swift，工程里没有 Swift 文件不会自动链 Swift 运行时；CMake 3.24 又开不了 Swift | 手动加 Swift 库的搜索路径和三个兼容库 |
| iPhone 上一启动就闪退（`EXC_BREAKPOINT`，栈顶 `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`；iOS 27.2） | iOS 27 起用新 SDK 编译的应用必须采用场景生命周期（UIScene），Cocos 的模板只有 AppDelegate | 加 `SceneDelegate`（`client/native/engine/ios/SceneDelegate.mm`）：场景连上时由 `AppDelegate startInWindowScene:` 建窗口、启动引擎和脚本桥，前后台切换由场景转给 AppDelegate 原来的方法；`Info.plist` 声明 `UIApplicationSceneManifest`；`CMakeLists.txt` 列进源文件 |
| 构建后启动图、`CMakeLists.txt` 的工程名被改 | Cocos 构建时按它的模板改写 | 工程名事先写好（`apply.mjs`）；启动图构建完 `git checkout` 换回来 |

## 5. 广告

**总开关**：`game.json` 的 `ads.enabled`（底座默认 `true`：上架的版本都有广告），改了要重新打包。`tools/native/apply.mjs` 按它改这几处：

| 开关 | `true` | `false` |
|---|---|---|
| `config/platform.json` 的 `adsEnabled` | 平台层用广告位 | 平台层当没有广告位：`hasCapability('ads')` 为假，看广告的入口全部隐藏（`docs/01` 7.1） |
| iOS `CMakeLists.txt` 的 `GAME_ADS` | 链广告 SDK（`./package.sh` 自动下载） | 不下载、不链，桥按没有广告编译，不弹 UMP、ATT |
| iOS `Info.plist`、`InfoPlist.strings` | 有 `GADApplicationIdentifier`、`NSUserTrackingUsageDescription`、`SKAdNetworkItems` | 这几项去掉（没有跟踪授权弹窗却写了说明，审核会问） |
| Android `app/build.gradle` 的 `GAME_ADS` | 依赖 AdMob、UMP，编 `app/ads/on/` 的 `GameAds.java` | 不依赖，编 `app/ads/off/` 的空实现 |
| Android `AndroidManifest.xml` 的广告 ID 权限 | 声明 | `tools:node="remove"` 去掉 |

浏览器试玩（`debug` 平台）也跟这个开关走，地址栏加 `?ads=1` / `?ads=0` 临时看另一种版本。

| 平台 | SDK | 广告位 ID 在哪 |
|---|---|---|
| 微信 | 流量主（`wx.createRewardedVideoAd` 等） | `game.json` 的 `ads.wechat`；空着 = 没有广告（开通流量主之前），看广告的入口自动隐藏（`docs/01` 7.1） |
| iOS | Google Mobile Ads + UMP（用户同意）+ ATT（跟踪授权） | `game.json` 的 `ios.admobAppId`（应用 ID）、`ads.ios`（广告位） |
| Android | Google Mobile Ads + UMP | `game.json` 的 `android.admobAppId`、`ads.android` |

`ads.ios`、`ads.android` 填 AdMob 后台建的真实广告位（底座里先填的是测试 ID，`docs/06` 第 1 节），`ads.test` 是 Google 官方的测试广告位。**只有上架包用真实的**：`./package.sh` 打 iOS IPA、Android AAB 时带 `GAME_RELEASE=1` 跑 `tools/native/apply.mjs`，其它产物（Xcode 工程、模拟器、装到手机、APK）和 `./run.sh native-apply` 都写测试广告位——测试时点到自己的真实广告会被 AdMob 判成无效流量。AdMob 应用 ID 一直用真的（UMP 的同意弹窗按它在后台的设置出）。打过上架包以后仓库里的 `config/platform.json` 是真实广告位，不要提交（再跑一次 `./run.sh native-apply` 就换回测试的）。做新游戏时 `ads.ios`、`ads.android` 先填测试 ID，上架前换成自己的。启动时先弹 UMP 的同意表（只有欧洲等需要的地区会弹），iOS 再弹 ATT 授权（不同意也能玩，只是广告不个性化），然后加载激励视频和插屏。加载失败（上架前和刚上架时填充很低、断网）隔一会儿自动再试：15 秒起逐次加倍，最长 5 分钟一次，成功就重置（`GameBridge.mm`、`GameAds.java`）；拉到之前看广告的入口是灰的。设置里的「隐私选项」（`hasCapability('privacy_options')`）能随时改同意。

## 8. 多语言

App（iOS、Google Play）做欧美、日韩和繁体区（不做中国大陆），语言跟着同类休闲游戏常做的那一套来（本地化行业说的 EFIGS + 中日韩，再加巴西葡萄牙文、俄文、土耳其文）；微信只有大陆用户，只带简体中文和英文。

| 代码 | 语言 | iOS `.lproj` | Android `values-` | 应用名 |
|---|---|---|---|---|
| `en` | 英文（App 默认） | Base、en | （默认） | `game.json` 的 `name.en` |
| `zh_CN` | 简体中文（微信默认） | zh-Hans | zh-rCN | `name.zh_CN` |
| `zh_TW` | 繁体中文（台湾、香港、澳门） | zh-Hant | zh-rTW、zh-rHK | `name.zh_TW` |
| `ja` | 日文 | ja | ja | `name.ja` |
| `ko` | 韩文 | ko | ko | `name.ko` |
| `de` `fr` `es` `it` `ru` `tr` | 德、法、西、意、俄、土耳其文 | 同代码 | 同代码 | 同代码 |
| `pt` | 葡萄牙文（巴西写法） | pt-BR | pt | `name.pt` |

- **各端带哪些**：`game.json` 的 `languages.app` / `languages.wechat`，`tools/native/apply.mjs` 写进 `config/platform.json`，平台层读成 `App.platform.languages`；同时生成各语言的应用名（iOS `<lproj>/InfoPlist.strings`，构建完由 CMakeLists 拷进 .app；Android `res/values-*/strings.xml`）和 Info.plist 的 `CFBundleLocalizations`。加语言：`apply.mjs` 的 `LOCALES` 加一行、`game.json` 加代码、`strings.csv` 加一列、`ui/i18n.ts` 的 `LANGUAGE_NAMES` 加名字。
- **选哪种**：设置里选过的优先；否则按系统语言（`platform.systemLanguage()` → `ui/i18n.ts` 的 `matchLanguage`：zh-Hant / TW / HK / MO 归繁体，其余中文归简体，其它按主语言），认不出用这一端的第一种。缺的条目繁体退简体、其它退英文。
- **怎么写**：每种语言按当地休闲游戏的说法写，不直译（日文「ログボ」「ステージ」等）；角色、卡的名字每种语言各起一套，不能和别的游戏、角色重名，也避开各地的粗话（例如英文的 Fanny 在英国是粗话）。
- **放不下就改短，不缩字**：`fit()` 在 DEBUG 下把每次缩字记进 `fitLog`；改完文案用假 cc 在 Node 里跑一遍全部页面和弹窗、收集 `fitLog`（临时脚本，不进仓库），每种语言都要 0 处缩字；卡名按名牌宽度量（30 号字、200 宽，中日韩约 6 个字）。
- **字体**：游戏字体（荆南麦圆体，boot 包）带除韩文以外全部语言用到的字；土耳其文的 ğ Ğ ş Ş İ 原字体没有，由 `font_subset.py` 用字体里的字母和附加符号拼成组合字形。韩文另裁一份资源圆体韩文版放 `resources/font/game_ko.ttf`（只有 App 用，不占微信主包），选韩文时 `ui/res.ts` 换上。加载页还没读到韩文字体，韩文提示由系统字体补字。
- **商店**：`store/listing.md` 每种语言一份；上架图每种语言一套（`store/briefs/posters/<画面>_<语言>.txt`），画完逐张看字。

## 9. 难度调试页（开发版才有，换游戏照用）

难度要能自己调、自己试；「以后我们其他游戏也可以这样来测，复用这个模块」；「只在开发版里面显示，代码可以保留」。底座的示例玩法接了整体三档、演示、作弊按钮；各档关卡要等新游戏有了关卡工具再接。

- **只在开发版出现**：`PlatformBase.isDevBuild()`——编辑器预览、调试构建（`cc/env` 的 `DEBUG`，即 `./run.sh` 打的网页版）。`./package.sh` 打的包（微信、iOS、Android）都是正式构建，一律不出；微信上传后的开发版、体验版也不出（打包的都要隐藏，否则体验版和审核时会露出来）。不用上架前改开关；`game.json` 的 `levelLab` 写 `false` 可以连开发版也关掉。原生（iOS、Android）现在都按 release 构建，所以原生包里没有。
- **底座部分**（`client/assets/scripts/devtools/`，换游戏不用改）：
  - `levelLab.ts`：各档关卡的索引、玩家挑了哪一档（存在本机，读关卡时先问 `lab.override(关卡号)`）、整体三档（-1 / 0 / 1）。
  - `labPage.ts`：页面本身（整体三档、翻关、每档一行、演示、试玩、恢复、作弊按钮、「已改」一览），内容超出屏幕就滚动。
- **游戏要给的**（`game/labHooks.ts`）：`LabHooks`——怎么试玩一关、怎么演示（示例玩法按关卡的参考解打）、整体三档具体改什么（示例是暂存槽 ±1 格和连击窗口，数在 `game_ui.json` 的 `labTiers`）、作弊按钮（金币、生命、进度）。Boot 里 `lab.init(platform, 整体档变了做什么)`，注册 `new LabPage(labHooks)`，设置里 `lab.enabled` 时放入口。
- **各档关卡**：关卡工具按「正常打法能过几成」每 10% 存一档到 `resources/config/levels_lab/`：`index.json`（关卡号 → `base` 包里用哪一档、`target` 目标 %、各档的 `natural` 正常打法能过 %、`think` 想清楚能过 %、`run` 路线最长连击）和 `level_XXXX_p{档}.json`。只给开发版用：`./package.sh` 构建前把整个目录挪出 `assets/`、构建完挪回来，打的包里没有（中途打断没挪回来的，下次运行开头先挪回来；暂存在 `client/.levels_lab_stash/`）。可以用关卡工具按机器人量出的过关率每 10% 存一档；新游戏的关卡格式不同也没关系：调试页把关卡当原始字典存，由游戏自己解析（示例玩法读字典里的 `ease`，`services/config.ts` 的 `loadLevel`）。

### 9.1 自动玩（开发版才有）

- 入口：设置里的「自动玩」（和难度调试页一样只在开发版出现，`devtools/autoPlay.ts` 的 `enabled()` = `isDevBuild()`，`./package.sh` 打的正式包没有）。小窗里 ±1、±10 选从第几关开始（默认当前关），点「开始」。按真实进度玩时这一关还没解锁，就把进度挪到这一关（和启动参数 `?level=` 一样）。
- 打法：局内由机器人点（`game/gameView.ts` 的代打）；过关后结算页播完，自己点「下一关」——和真人点一样走 `Flow.afterResult`，礼包、插屏照常出；输了不弹复活和失败窗，记一次失败后重打（连输照样降档，不扣命）；打到最后一关回主页。
- 广告：照真实规则出（第 5 节、`docs/01` 7.1 的频控），模拟广告页（`ui/mockAd.ts`）1.5 秒后自己关，所以自动玩时看得到广告的节奏。
- 停：屏幕左边一直挂着「停止自动玩」（换页也在），点了这一关接着自己玩。
- 启动参数 `?autoplay=1&level=N&autoTo=M`（`./run.sh auto N M`）走同一套。换玩法时代打用的是 `rules.ts` 的 `hint()`，不用改这里。
