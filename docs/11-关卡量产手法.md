# 11 关卡量产手法：拆开来，按需取用

这份文档把「怎么又快又稳地做出几百上千关」拆成一件件能单独取用的手法，每件写清：怎么做、省在哪、代价、会不会坏可解、在底座里怎么落。

来源有两处：一是底座自己的做法（`docs/02` 5.8、5.9），二是对一款同类上线竞品关卡数据做的统计（2026-11）。这款竞品的玩法是物品装在容器里，点一下送进目标，三个一组。这里只记做法和统计数字，不收它的关卡、美术和文案（CLAUDE.md 第 1 条：只借鉴品类玩法）。

**怎么用**：新游戏在 `docs/01` 第 2 节写明用了这里哪几件、参数是多少。标了「大改」的，先讲给用户，确认后再做（CLAUDE.md「开发流程」）。

## 1. 名词

不同玩法叫法不一样，这份文档统一这么叫：

| 名词 | 指什么 | 例子 |
|---|---|---|
| 种类 | 规则上要凑成一组的那个属性 | 鱼种、花色、图案 |
| 件 | 一个能点的东西 | 一条鱼、一朵花、一块牌 |
| 容器 | 装件的东西，空了就消失 | 泡泡、绳子、牌堆 |
| 目标 | 要某一种件、装满就送走的东西 | 鱼缸、花盆、订单 |
| 暂存槽 | 点了但没有目标要的件先放这里，放满就输 | |
| 底图 | 一关的骨架：有几个容器、每个装几件、哪几件是同一种 | |
| 换皮 | 种类编号整体对调，结构、难度、参考解都不变（`docs/02` 5.9 的「换图案」） | |
| 覆盖层 | 挂在底图上的机制：冰冻、锁链和钥匙、问号、计数锁、石头…… | |
| 参考解 | 按这个顺序点一定能过的一串点击，生成时带上，`level-verify` 按它重放 | |

## 2. 竞品是怎么量产的（2026-11 统计）

| 看什么 | 数字 |
|---|---|
| 关卡数 | 1000 关；打完第 1000 关，从第 5 关起循环 |
| 关卡文件写什么 | 只写容器、每个容器装哪几件、挂什么机制。**不写目标顺序，不写坐标** |
| 底图 | 第 21–1000 关共 980 关，其中 845 关（86%）出自 3 张底图，每档难度一张：普通 33 个容器 123 件，难 44 个 162 件，超难 50 个 183 件。各关之间只是换了种类、挂了不同机制，有的多塞几个不装件的石头 |
| 一张底图出多少关 | 用得最多的一张出了 265 个不同的关卡文件，机制组合 104 种 |
| 件怎么分进容器 | 难、超难两张，和随机洗牌在统计上分不出来；普通那张同种件明显更扎堆：同一容器里的同种对子有 30 对，随机洗牌一般 18 对 |
| 难度参数 | 第 51 关以后，整张关卡表只有 4 行，四关一轮：普通（限时 180 秒、1 段难点）、难（240 秒、2 段，有两种写法）、超难（300 秒、3 段） |
| 目标 | 开局后按局面现挑。平时挑屏幕上最多的种类；进度落进「难点窗口」时，专挑屏幕上快没了或者根本没有的种类。窗口全在进度 28%–80% 之间；失败页显示「进度 xx%」 |
| 机制 | 13 种，从第 4 关到第 601 关陆续解锁。一张表管解锁，同时驱动首发说明弹窗和结算页的「离下一个新玩法」进度条 |
| A/B | 关卡表另有变体表，只写改了的关（第 3–250 关里写了 208 关），读不到就回落到基础表；机制解锁表也分了组 |
| 后段 | 第 701–1000 关有 148 关和它前面第 4 关一模一样；第 601–1000 关有 38% 一个机制都不挂 |

它快在三点：

1. 不保证可解，靠现挑目标兜底；
2. 难度主要不靠关卡文件，靠一张很小的参数表；
3. 底图极少，靠换皮和挂机制凑数量。

第 1 点和硬约束第 7 条（关卡必须可解）冲突，不照搬；第 2、3 点能拿来用，见第 4 节。

## 3. 手法一览

| 节 | 手法 | 一句话 | 适用 | 底座现状 | 会不会坏可解 |
|---|---|---|---|---|---|
| 4.1 | 底图 + 换皮 | 每档几张底图，每关换种类、换摆法 | 所有玩法 | **已有**（`docs/02` 5.9） | 不会 |
| 4.2 | 机制覆盖层 | 同一张底图挂不同机制，就是不同的关 | 有机制的玩法 | 新 | 照 4.3 放就不会 |
| 4.3 | 按参考解放机制 | 机制只放在参考解走得通的位置 | 有参考解的玩法 | 新（`docs/02` 第 4 节「按解构造」的延伸） | 不会 |
| 4.4 | 生成参数、运行参数分开 | 难度旋钮分两类：改了要重新生成的，改了只要重量的 | 所有玩法 | 部分有（`clock`、暂存槽加减） | 只放宽的不会 |

| 4.6 | 不换布局的降档 | 连输以后只放宽运行参数，不另外生成 | 所有玩法 | 新（现在降档是少一种图案） | 不会 |

| 4.9 | 一张解锁表驱动几处 | 第几关出哪个机制只写一处 | 有机制的玩法 | 新 | 不涉及 |
| 4.10 | 变体表 + 回落 | A/B 测难度，变体表只写改了的关 | 要做 A/B 时 | 新 | 每个变体照样校验 |
| 4.11 | 目标现挑（大改） | 关卡不写目标顺序，开局后按局面挑 | 有目标、订单的玩法 | 新 | 要换一种校验法 |

## 4. 各手法怎么做

### 4.1 底图 + 换皮（已有）

做法见 `docs/02` 5.9：每档几个模板，换图案、换摆法，同一个模板前后隔 `templateGap` 关以上。竞品的数据补两点：

- **底图可以比想的少**：它一档只用一张底图就撑了几百关，靠的是换皮加覆盖层（4.2）。底座每档本来就有几个模板，再挂覆盖层，同样多的模板能出多得多的不同关。
- **换皮以后，同一关里的种类仍要一眼分得清**：颜色、轮廓都不能撞。

### 4.2 机制覆盖层

- 一关 = 底图 × 换皮 × 覆盖层。覆盖层只写「哪几个容器、哪几件挂什么机制，参数多少」，和底图分开存。
- **覆盖层算进模板**：同一张底图配 k 种覆盖层，就是 k 个模板，每个用 `./run.sh level-pick` 量一次。之后照 5.9 换皮、换摆法，覆盖层跟着一起换，难度不变，不用再量。这样底图可以少生成几张，模板数照样多。
- **挂什么**：只从已经解锁的机制里挑（解锁表见 4.9）。每关挂几种照 `docs/02` 5.2 的节奏，单关上限写进 `levels.json`。
- **不要每关现挑覆盖层**：覆盖层会改变难度，现挑就得每关重量，丢了 5.9「不用再量」的好处。

### 4.3 按参考解放机制（覆盖层不坏可解）

这是 `docs/02` 第 4 节「按解构造」在机制上的延伸：先有参考解（第几步点哪一件），机制只放在参考解走得通的地方。这样 `level-verify` 按参考解重放一定能过，不用另外求解。

| 机制 | 怎么打开 | 能放在哪 |
|---|---|---|
| 计数锁 | 全场每拿走一件减 1，到 0 打开 | 参考解第 k 步才第一次用到的容器，计数不超过 k − 1 |
| 钥匙 + 锁 | 清空带钥匙的容器（或拿走钥匙件），开一把锁 | 参考解里钥匙那一步，早于被锁的容器第一次被用到 |
| 冰冻 | 旁边的容器每被拿一次，化一层 | 参考解里，它第一次被用到之前，旁边被拿的次数不少于层数。「旁边」要写在数据里，不能靠物理位置现算 |
| 遮罩 | 某一种件被拿走以后揭开 | 参考解里那一种第一次被拿，早于被遮的容器第一次被用到 |
| 连体件 | 一次拿走两件 | 参考解里这两件连着拿，拿的时候暂存槽空位够 |
| 问号件 | 点一下翻开，再点才拿 | 不影响可解，只增加看信息的成本，放哪都行；参考解里补上翻开那一下 |
| 未知容器 | 打开前点不了（比如落到底、或者上面清空才显形） | 和计数锁一样：参考解里，它第一次被用到之前，打开条件已经满足 |
| 石头、计数障碍 | 只占地方（计数障碍数到 0 消失） | 不影响可解；但会改变布局或遮挡的玩法，挂上以后要重新校验 |

找不到合法位置，就换一种机制或者换种子，不要硬放。

### 4.4 生成参数和运行参数分开

| 类 | 例子 | 改了以后 |
|---|---|---|
| 生成参数 | 规模（种类数、件数、容器数或层数）、扎堆度（4.7）、覆盖层 | 重挑这一档的模板（`./run.sh level-pick`） |
| 运行参数 | 限时秒数、暂存槽格数、开局目标位、技能免费次数、目标现挑的难点窗口（4.11） | 不用重新生成；`./run.sh level-pick --probe` 重量，偏出目标再重挑 |

- 竞品的难度主要在运行参数里：每档只有一张底图，第 51 关以后整张参数表只有 4 行。
- 底座里建议每档在 `levels.json` 的 `tiers` 下把这两组分开写；改难度时先动运行参数。
- **只往宽松改的运行参数**（多一格暂存、多给时间）不会让参考解失效，不用重新校验。

### 4.5 难点放在进度中段

- 竞品的难点窗口全在进度 28%–80%：开头好上手，最后 20% 不刁难。这样输的时候多半已经打了一大半，失败页又写着「进度 xx%」，玩家觉得差一点，就愿意复活。
- **订单写死、或者按解构造的玩法**：生成参考解时，把「故意先放进暂存槽」的那几步（暂存槽最满的时候）排在参考解的 30%–80% 段，最后 20% 只排能直接送走的件。
- **量**：机器人统计「输在哪个进度」。目标是失败集中在中后段，而不是开头。
- 失败页显示进度属于界面改动，要做先问用户（CLAUDE.md 第 11 条）。

### 4.6 不换布局的降档

- 竞品同一张底图按种子抽启用几段难点，同一张图就有不同难度。底座可以拿同样的思路做连输降档：不另外生成「少一种图案」的版本，只放宽运行参数，比如多一格暂存、多给时间、关掉一段难点窗口。
- 好处：布局不变，参考解照样能过，不用再生成、再校验；玩家重进还是那一关，只是松一点。
- 现状：示例玩法的降档是 `generate(..., ease)`，少一种图案（`docs/02` 第 4 节）。改成这一种是玩法层的改动，新游戏自己选。

### 4.7 扎堆度

- 扎堆度：同一个容器里（或者参考解里挨着的几步里）同种件有多少。扎堆多就容易，打散就难。具体怎么算，由玩法自己定义。
- 竞品普通档的底图，同种对子比随机洗牌多七成（30 对比 18 对）；难、超难两档和随机一样。
- 用法：当成生成参数放进 `tiers`，放松档、普通档调高。量出来偏难时先调它，比加减种类更细。

### 4.8 关卡文件不写坐标

- 竞品的关卡文件只写容器的顺序和每个装什么；位置由代码按顺序一排排摆好，再用物理压实。文件小，镜像、打乱位置都不费事，改了美术尺寸也不会把关卡弄坏。
- 有遮挡的玩法：遮挡要么写成关系（谁压着谁），要么由坐标算；由坐标算的，换摆法只能用不改变遮挡的变换（示例玩法的左右镜像）。
- 位置如果是物理现算的（会滚、会挤），就不能拿来定遮挡、相邻这些规则，否则同一关每次打，规则都不一样。

### 4.9 一张解锁表驱动几处

- 第几关出哪个机制只写一处：配置里一张表（CLAUDE.md 第 5 条，数值不进代码）。这张表同时管三件事：首发关的说明弹窗、覆盖层能挑哪些机制、结算页「离下一个新玩法还有几关」（这一项要做的话是界面改动，先问用户）。
- 竞品把 13 种机制拖到第 601 关才出完；底座照 `docs/02` 5.2，前 20 关出完。这一点不照搬。

### 4.10 变体表 + 回落（关卡 A/B）

- 一张基础关卡表加几张变体表。变体表只写改了的关；读关时先查变体表，没有再回落到基础表。竞品连机制解锁表也分了组。
- 底座没有服务器：分组在安装时本地随机定、记进存档，统计事件带上分组（`docs/10` 5.1）。每个变体都要过 `level-verify`。
- 默认不开，要测的时候再加。这是代码改动，先讲方案。

### 4.11 目标现挑（大改，只适用于有目标、订单的玩法）

**做法**（竞品）：关卡不写目标顺序；每空出一个目标位，按当前局面现挑一种。

- **友好**：屏幕上（含暂存槽）扣掉在架目标还缺的件数以后，剩得最多、又不在架上的那一种。
- **刁难**（只在难点窗口里，同样先扣掉在架目标还缺的件数）：按顺序挑——屏幕上只剩 2 件以内的种类；没有就挑屏幕上一件都没有的；再没有就挑数量不是 3 的倍数、而且最少的那一种。
- **难点窗口**：每关配几段进度区间。开局按权重抽这一局启用几段，权重的字段名就是「预计看 0 / 1 / 2 / 3 次广告」。随机种子是关卡号，所以同一关每次抽到的一样。

**省在哪**：件怎么分都能玩，只要每种是 3 的倍数；不用排目标顺序，也不用按解构造。同一张底图靠窗口段数，就能当不同难度用。

**代价**：

- 难度来自运气，不来自路线。玩家不知道后面要什么，目标还跟着局面变，没法规划，和 `docs/02` 第 6 节「难在点击顺序」正相反。
- 「可解」要重新定义：目标跟着点法变，只能在这套挑法下搜一条解。

**要用的话**（先经用户确认）：

- 挑法写成 `core/` 里的纯函数：输入局面和种子，不碰 `Math.random`。这样 `level-verify` 能重放。
- 生成时，用「想清楚」的机器人在这套挑法下找一条参考解，写进关卡；找不到就换种子。难度仍用只看屏幕的机器人量（`docs/02` 第 6 节）。
- **温和用法**：只用友好挑法，不开刁难窗口，当降难度的工具（新手期、连输降档），关卡数据不用改。

## 5. 组合方案

| 方案 | 用哪几件 | 适合 |
|---|---|---|
| A 保可解量产（默认） | 4.1 + 4.2（覆盖层算进模板）+ 4.3 + 4.4 + 4.5 + 4.6 + 4.7 | 所有玩法；全部硬约束都满足 |
| B 加温和目标 | A + 4.11 只用友好挑法 | 有目标的玩法，前期或降档要更松 |
| C 竞品式 | 4.11 带刁难窗口 + 随机填 + 少量底图 | 大改，由用户定；要保可解，照 4.11「要用的话」做 |

方案 A 的产能：一档 k 张底图配 m 种覆盖层，就是 k × m 个模板，每个只量一次；关卡数不限，`templateFor` 按关卡号现排。

## 6. 不照搬的

- **不保可解**：违反硬约束第 7 条。
- **机制拖到第 601 关才出完**：多数玩家打不到第 80 关（`docs/02` 5.1）。
- **后段原样重复，后段大量关不挂机制**（竞品第 601–1000 关有 38%）：底座的模板能无限排；同一模板前后隔 `templateGap` 关以上，而且换皮、换摆法、覆盖层至少换一样。
- **一档只用一张底图**：太容易被玩家认出来。
